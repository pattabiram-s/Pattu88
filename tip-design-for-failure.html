Reliability

Cover the outages you'll actually have

Goal: the boring killers alert early, and rollback is one command you’ve rehearsed.

  1. Alert on disk before it’s full

    Warn at 80%, page at 90% — not at 100%.

  2. Check certificate expiry daily

    Alert under 14 days left.

    exp=$(echo | openssl s_client -connect api.example.com:443 2>/dev/null \
     | openssl x509 -noout -enddate | cut -d= -f2)
# compare $exp to now; alert if < 14 days

  3. Watch the deploy for 10 minutes

    Most bad deploys spike error rate or latency right after rollout. Auto-revert on it.

  4. Keep rollback to one rehearsed command

    Pin the last known-good tag and practise the undo.

    kubectl rollout undo deploy/web
kubectl rollout undo deploy/web --to-revision=42

  5. Automate the fix you’ve done twice

    Liveness restarts a wedged process; logrotate stops the disk filling; a cron handles the token refresh.

  6. Run a game day

    Actually trigger the failure and time recovery. An untested runbook is a hope.
