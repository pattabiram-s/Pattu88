Make pipelines fail fast, loudly

Goal: sub-5-minute PR feedback, and a red build that names the one thing that broke.

  1. Split a fast gate from the heavy jobs

    Put lint + type-check + unit tests in one job and make build/integration needs: it, so they never run when the gate is red.

    jobs:
  gate:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run lint && npm run typecheck && npm test -- --bail
  build:
    needs: gate            # skipped if gate fails
    timeout-minutes: 15
    runs-on: ubuntu-latest

  2. Cap every job's runtime

    timeout-minutes turns a hung step into a fast failure instead of a 6-hour bill.

  3. Stop at the first failing test

    Don’t run 400 tests to report the first break.

    pytest --maxfail=1 -q        # or: npm test -- --bail

  4. Make the failure self-explaining

    Emit an annotation on the exact file/line and a one-line summary.

    echo "::error file=src/auth.ts,line=42::expired-token check returns undefined"
echo "### ❌ auth > rejects expired token" >> "$GITHUB_STEP_SUMMARY"

  5. Quarantine flakes, don’t blanket-retry

    A global “retry 3×” hides real regressions. Skip the flaky test, open a ticket, keep green trustworthy.
