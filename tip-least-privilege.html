Scope an IAM role to exactly what it uses

Goal: a role with no wildcards, carrying only the permissions the workload actually calls.

  1. Start from deny-by-default

    Create the role with a trust policy only — no permissions yet.

  2. Capture what it actually used

    Run the workload, then ask AWS which services the role touched.

    aws iam generate-service-last-accessed-details --arn "$ROLE_ARN"
aws iam get-service-last-accessed-details --job-id "$JOB_ID"

  3. Generate a tight policy from CloudTrail

    Let Access Analyzer draft a least-privilege policy from real activity.

    aws accessanalyzer start-policy-generation \
  --policy-generation-details '{"principalArn":"'$ROLE_ARN'"}'

  4. Constrain resource and context

    Lock each action to specific resources and conditions.

    { "Effect":"Allow", "Action":["s3:GetObject"],
  "Resource":"arn:aws:s3:::acme-reports/${aws:PrincipalTag/team}/*",
  "Condition":{"StringEquals":{"aws:ResourceAccount":"111122223333"}} }

  5. Swap static keys for short-lived creds

    CI → GitHub OIDC assume-role; EKS pods → IRSA/Pod Identity.

  6. Block wildcards in review

    Fail the PR when someone reaches for *.

    checkov -d . --check CKV_AWS_1,CKV_AWS_49   # or: tfsec .
