Secrets

Keep secrets out of images and repos

A leaked key in a container layer or git history is a breach waiting to be indexed — inject secrets at runtime instead.

Inject at runtime, scoped and short

Pull credentials from a secrets manager at start-up or request time, scope each to exactly what it needs, and prefer short-lived tokens over permanent keys. The application should receive a secret, not ship with one.

Images and history are forever

A secret baked into a container layer or committed to git stays in the history even after you ‘delete’ it, and public scanners index leaked keys within minutes. Assume anything that ever touched a repo or a registry is already compromised.

Rotate, and prove you can

Rotation only helps if it actually works under pressure. Rotate on a schedule, automate it, and test it — a key you’re afraid to rotate is a key you can’t revoke when it leaks.

Catch leaks before they merge

Run secret scanning in pre-commit and in CI so a key is caught in the pull request, not in production. Pair it with a rotation runbook so the answer to ‘a key leaked’ is routine, not a fire drill.
