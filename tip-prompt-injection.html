LLM Security

Defend an LLM app against prompt injection

Goal: retrieved documents, tool outputs and user text can’t override your instructions or trigger unsafe actions.

  1. Separate instructions from data

    Put policy in the system prompt; pass user and retrieved content as clearly-delimited data — never concatenate it into instructions.

  2. Treat tool output and RAG docs as hostile

    Content fetched from the web, tickets or a vector store is untrusted input. It must not be able to issue tool calls or change the task.

  3. Constrain the tools, not just the prompt

    Allowlist tools, give each least privilege, and require human approval for anything with side effects (send, delete, pay).

    # the model proposes; a deterministic layer authorises
if action.name not in ALLOWED or action.risk == "high":
    require_human_approval(action)

  4. Filter in and out

    Scan inputs for known injection patterns and outputs for secrets/PII before anything leaves the system.

  5. Red-team before you ship

    Run a known injection suite in CI and fail on a successful exfiltration.

    # e.g. garak / promptfoo red-team suite as a CI gate
promptfoo eval -c redteam.yaml --fail-on-score 0.9
