Observability

Instrument to pivot metric → trace → log

Goal: from an alert, reach the exact slow request in minutes — no guessing.

  1. Log structured JSON with a trace id

    The trace_id is what lets you join signals.

    {"ts":"2026-10-10T09:12:04Z","level":"error","svc":"checkout",
 "trace_id":"4bf92f3577b34da6","msg":"charge failed","latency_ms":812}

  2. Emit RED metrics per service

    Rate, Errors, Duration (p50/p95/p99); USE for the resources under them.

  3. Propagate the trace header everywhere

    W3C traceparent across every hop — OpenTelemetry auto-instrumentation does most of it.

  4. Alert on symptoms, not CPU

    Page on error rate and p99 latency.

    histogram_quantile(0.99,
  sum by (le,route) (rate(http_request_duration_seconds_bucket[5m])))

  5. Wire exemplars to jump to traces

    Click a spike and land on the slow trace.
