Shift security left, but gate at the right

Catch issues in the PR where they're cheap to fix, and still enforce a hard policy at admission and runtime — both, not either.

Scan in the pull request

Find the problem where the fix is a quick edit: images, IaC and secrets, all on the PR.

trivy fs --scanners vuln,secret,misconfig .   # deps + keys + bad config
tfsec .            # or: checkov -d .            # IaC misconfig
gitleaks detect --source . --redact            # committed secrets

Enforce at admission — shifting left doesn’t replace the gate

Early feedback reduces what reaches prod; it doesn’t guarantee it. Block the risky things at the cluster door with a policy engine.

# Kyverno: refuse :latest and unsigned images
apiVersion: kyverno.io/v1
kind: ClusterPolicy
spec:
  validationFailureAction: Enforce
  rules:
    - name: disallow-latest
      match: { any: [{ resources: { kinds: [Pod] } }] }
      validate:
        message: "Pin an image tag; :latest is not allowed"
        pattern: { spec: { containers: [{ image: "!*:latest" }] } }

Verify provenance at runtime

cosign verify --key cosign.pub registry/acme/web:1.8.2   # signed by us?

Keep the gate trusted

A slow or noisy gate gets bypassed. Keep scans fast, tune out false positives, and make the required fix obvious — a gate people route through, not around.
