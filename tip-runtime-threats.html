Threat Detection

Detect runtime threats with eBPF

Goal: get alerted the moment a container does something it never should — a shell, an unexpected connection, a write to /etc.

  1. Deploy Falco with the eBPF driver

    A DaemonSet taps the kernel via eBPF — no app changes.

    helm repo add falcosecurity https://falcosecurity.github.io/charts
helm install falco falcosecurity/falco --set driver.kind=ebpf

  2. Keep the defaults, add one sharp rule

    Start with the shipped ruleset; add what matters to you.

    - rule: Shell in a production pod
  condition: spawned_process and container and proc.name in (bash, sh, zsh)
           and k8s.ns.name = "prod"
  output: "Shell in prod (pod=%k8s.pod.name cmd=%proc.cmdline)"
  priority: WARNING

  3. Route alerts somewhere humans look

    Falcosidekick fans out to Slack/SIEM/webhook.

    helm upgrade falco falcosecurity/falco \
  --set falcosidekick.enabled=true \
  --set falcosidekick.config.slack.webhookurl=$SLACK_URL

  4. Tune the noise

    Add exceptions for known-good behaviour so real alerts stay rare and trusted.

  5. Make detections rare by hardening

    Read-only root filesystem + dropped capabilities means a shell-in-container is genuinely abnormal.
