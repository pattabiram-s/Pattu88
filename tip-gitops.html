GitOps

Deliver with GitOps, not kubectl apply

Goal: cluster state equals git, deploys are pull requests, and manual drift is reverted automatically.

  1. Install a GitOps controller

    Argo CD (or Flux) watches a repo and reconciles the cluster to it.

    kubectl create namespace argocd
kubectl apply -n argocd -f \
  https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml

  2. Describe the app as code

    Point an Application at the repo path; turn on auto-sync, prune and self-heal.

    apiVersion: argoproj.io/v1alpha1
kind: Application
metadata: { name: web, namespace: argocd }
spec:
  source: { repoURL: git@github.com:acme/infra.git, path: envs/prod/web, targetRevision: main }
  destination: { server: https://kubernetes.default.svc, namespace: web }
  syncPolicy:
    automated: { prune: true, selfHeal: true }

  3. Deploy by merging, never by hand

    A change is a PR to the manifests; the controller rolls it out. No one runs kubectl apply against prod.

  4. Let self-heal revert drift

    Someone hotfixes a live Deployment? selfHeal snaps it back to git — config stays reproducible.

  5. Roll back with git

    Reverting the commit reverts the cluster.

    git revert <bad-sha> && git push    # Argo syncs the rollback
