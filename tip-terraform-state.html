Make Terraform state locked and recoverable

Goal: remote state that can’t be raced, is versioned for rollback, and is never hand-edited.

  1. Create a versioned, encrypted bucket + lock table

    S3 versioning = rollback; DynamoDB = the lock that stops two applies racing.

    aws s3api put-bucket-versioning --bucket acme-tfstate \
  --versioning-configuration Status=Enabled
aws dynamodb create-table --table-name tf-locks \
  --attribute-definitions AttributeName=LockID,AttributeType=S \
  --key-schema AttributeName=LockID,KeyType=HASH --billing-mode PAY_PER_REQUEST

  2. Point the backend at it

    One state file per environment + component keeps blast radius small.

    terraform {
  backend "s3" {
    bucket = "acme-tfstate"
    key    = "prod/network/terraform.tfstate"
    region = "ap-south-1"
    dynamodb_table = "tf-locks"
    encrypt = true
  }
}

  3. Migrate existing state

    Moves local state into the remote backend once.

    terraform init -migrate-state

  4. Back up before any surgery

    Never edit the JSON by hand. Pull a copy, then use state subcommands with a lock timeout.

    terraform state pull > backup.tfstate
terraform state mv aws_instance.old aws_instance.new
terraform import -lock-timeout=120s aws_s3_bucket.logs acme-logs

  5. Catch drift on a schedule

    Exit code 2 means reality diverged from code.

    terraform plan -detailed-exitcode   # 0 none, 2 drift
