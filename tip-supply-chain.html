Prove your build's provenance (SBOM + SLSA)

Goal: every artifact carries an SBOM, a signature, and attestation of how it was built — verified before it runs.

  1. Generate an SBOM at build

    A machine-readable bill of materials for what’s inside the image.

    syft packages registry/acme/web:1.8.2 -o spdx-json > sbom.spdx.json

  2. Sign the image and attach the SBOM

    Keyless with the CI’s OIDC identity — no long-lived keys.

    COSIGN_EXPERIMENTAL=1 cosign sign registry/acme/web:1.8.2
cosign attest --predicate sbom.spdx.json --type spdxjson registry/acme/web:1.8.2

  3. Emit SLSA build provenance

    Prove which source + workflow produced the artifact (GitHub’s attestations or slsa-github-generator).

    # GitHub Actions
- uses: actions/attest-build-provenance@v1
  with: { subject-name: registry/acme/web, subject-digest: ${{ steps.build.outputs.digest }} }

  4. Verify at admission, not just at build

    A policy controller refuses images that aren’t signed and attested by your pipeline.

    cosign verify --certificate-identity-regexp '.*@acme\.com' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  registry/acme/web:1.8.2

  5. Re-scan the SBOM for new CVEs

    Yesterday’s clean image is today’s CVE. Scan stored SBOMs on a schedule.

    grype sbom:sbom.spdx.json --fail-on high
