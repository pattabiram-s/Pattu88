Kubernetes

Give every pod requests, limits, and probes

Goal: four fields per workload that remove a whole category of cluster incidents.

  1. Set requests from observed usage

    Without them the scheduler guesses and packs nodes wrong. Base them on kubectl top/VPA.

    resources:
  requests: { cpu: 100m, memory: 128Mi }
  limits:   { cpu: 500m, memory: 256Mi }

  2. Add a readiness probe

    Keeps traffic off a container until it’s ready — no 502s mid-deploy.

    readinessProbe:
  httpGet: { path: /healthz, port: 8080 }
  periodSeconds: 10

  3. Add a liveness probe

    Restarts a wedged process automatically.

    livenessProbe:
  httpGet: { path: /healthz, port: 8080 }
  initialDelaySeconds: 15

  4. Add a startup probe for slow starters

    Stops liveness killing an app that just boots slowly.

    startupProbe:
  httpGet: { path: /healthz, port: 8080 }
  failureThreshold: 30
  periodSeconds: 5

  5. Protect availability, then templatise

    Add a PodDisruptionBudget, then bake all of this into the Helm chart base.
